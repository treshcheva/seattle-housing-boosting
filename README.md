# Seattle Housing Prices — Gradient Boosting Benchmark

Исследовательский pet project по прогнозированию стоимости жилья в Сиэтле. Сравниваются четыре реализации градиентного бустинга, их чувствительность к гиперпараметрам, время работы и экспериментальное объединение моделей.

## Проблема и актуальность

В прикладной регрессии важны не только точность, но и вычислительная эффективность, устойчивость к настройкам и переобучению. Цель проекта — сравнить распространённые реализации градиентного бустинга на одном наборе данных.

## Данные

Используется `houses_train.csv` — данные о недвижимости в Сиэтле с целевой переменной `price`. Файл **не приложен** к исходному ноутбуку и не включён в репозиторий. Для воспроизведения нужно самостоятельно разместить файл рядом с ноутбуком. Из признаков исключаются `id`, `date`, `zipcode`.

## Методы и метрики

- **Модели:** scikit-learn `GradientBoostingRegressor`, XGBoost, LightGBM, CatBoost.
- **Эксперименты:** влияние `n_estimators`, `max_depth`, `learning_rate`, L1/L2-регуляризации; визуализация деревьев; время обучения и предсказания.
- **Основная метрика:** MAPE (средняя абсолютная процентная ошибка).
- **Дополнительный эксперимент:** линейная метамодель на прогнозах XGBoost, LightGBM и CatBoost.

**Единицы MAPE:** в основной части пользовательская функция возвращает проценты (×100); в разделе стекинга используется `mean_absolute_percentage_error` из scikit-learn, возвращающая доли единицы. Не сравнивайте эти значения без пересчёта.

## Результаты

В [`seattle_housing_boosting_portfolio.ipynb`](seattle_housing_boosting_portfolio.ipynb) сохранены **оригинальные результаты выполнения**: графики зависимости MAPE от параметров, визуализации деревьев и замеры времени. Ячейки не запускались повторно при оформлении проекта. Для конкретных значений и графиков откройте ноутбук.

В исходных текстовых выводах отмечено, что современные реализации бустинга обучались быстрее классической реализации scikit-learn при сравниваемых настройках. Это наблюдение относится к данному эксперименту и не является универсальным утверждением о скорости библиотек.

### Ограничение стекинга

В исходном коде второе разбиение `train_test_split` выполняется снова на **полном датасете**, поэтому train/validation/test могут пересекаться. Полученные метрики стекинга не являются надёжной независимой оценкой. **Не следует заявлять улучшение качества за счёт стекинга на основании этих результатов.** Для исправления нужен новый эксперимент с непересекающимися выборками или out-of-fold прогнозами.

## Запуск

```bash
pip install numpy pandas matplotlib seaborn scikit-learn xgboost lightgbm catboost tqdm jupyter
jupyter notebook seattle_housing_boosting_portfolio.ipynb
```

Для повторного выполнения потребуется файл `houses_train.csv`. **Повторный запуск не нужен, чтобы просмотреть сохранённые выводы** — они встроены в ноутбук.
